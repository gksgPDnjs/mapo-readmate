# ReadMate 프로젝트 한눈에 보기

## 1. 이 프로젝트는 무엇인가요?

ReadMate는 사용자가 몇 가지 질문에 답하면, 현재 독서 취향에 맞는 책을 추천해 주는 서비스입니다.

핵심 원칙은 간단합니다.

- **데이터베이스(DB)**가 질문, 답변, 책, 추천 결과를 기억합니다.
- **추천 로직**이 DB에 있는 책 중에서 조건에 맞는 후보를 고릅니다.
- **AI(Gemini)**는 책을 고르지 않고, 이미 고른 책의 추천 이유를 짧게 설명합니다.
- 화면은 DB와 API에서 받은 정보를 보여 줍니다.

즉, AI가 근거 없이 책을 만들어 내는 방식이 아니라 DB에 등록된 책을 중심으로 추천하는 구조입니다.

## 2. 사용자 흐름

```text
학생이 1차 질문 12개에 답함
        ↓
답변이 DB에 저장됨
        ↓
4가지 독서 성향 계산
        ↓
DB에서 조건에 맞는 책 후보 찾기
        ↓
추천 3권과 추천 이유 저장
        ↓
화면에 성향과 추천 결과 표시
        ↓
사용자의 좋아요·싫어요 같은 피드백 저장
```

그다음 더 자세한 추천을 원하면 2차 질문 8개를 사용합니다. 2차 질문에서는 장르, 분위기, 문체, 읽기 목적, 피하고 싶은 요소 등을 고릅니다.

## 3. 맡을 수 있는 역할

| 역할 | 하는 일 | 이번에 진행한 내용 |
| --- | --- | --- |
| 사용자 또는 학생 | 질문에 답하고 추천을 확인 | 1차 12문항과 2차 8문항 흐름을 사용할 수 있게 구성 |
| 프런트엔드 개발자 | 화면과 버튼을 만듦 | 정적 질문 대신 DB에서 질문을 불러오고 답변을 저장하도록 연결 |
| 백엔드 개발자 | 화면과 DB 사이의 API를 만듦 | 세션 생성, 답변 저장, 성향 계산, 추천 결과 조회, 피드백 저장 API 추가 |
| DB 개발자 | 데이터가 안전하게 저장될 구조를 만듦 | 질문, 답변, 성향, 추천 실행, 추천 항목, 공개 결과 코드를 저장하는 테이블과 migration 구성 |
| 데이터 수집 담당 | 책 정보를 모으고 확인 | Open Library 후보 500권 수집 경로와 국립중앙도서관 연동 경로 준비 |
| 큐레이터 또는 사서 | 책 정보와 특성을 검토 | 책을 공개 추천에 넣기 전 상태와 특성값을 검수하는 구조 마련 |
| QA 담당 | 실제로 잘 되는지 확인 | 자동 테스트, DB 진단 화면, 추천 흐름 검사, 전체 시연 검사 작성 |
| AI 담당 | 추천 이유 문장을 만듦 | Gemini 선택 사항 연결과 API 키가 없을 때의 안전한 문장 대체 기능 추가 |

## 4. DB에는 무엇을 저장하나요?

| DB 정보 | 쉽게 말하면 |
| --- | --- |
| 책과 판본 | 같은 작품이라도 출판사나 ISBN이 다른 책을 구분하는 정보 |
| 책 특성 | 소설, 과학, 힐링, 난이도, 문체처럼 추천에 쓰는 표지판 |
| 질문과 선택지 | 1차 성향 질문 12개와 2차 정밀 질문 8개 |
| 익명 세션 | 로그인 없이도 한 번의 추천 과정을 구분하는 번호 |
| 답변 | 사용자가 고른 선택지 |
| 성향 스냅샷 | 그 시점에 계산된 4가지 독서 성향 결과 |
| 추천 실행과 항목 | 어떤 조건으로 어떤 책을 추천했는지 남기는 기록 |
| 피드백 | 추천을 봤는지, 마음에 들었는지 같은 반응 |

## 5. 지금까지 완성된 기능

### 질문과 추천

- 1차 질문 12개를 DB에서 불러옵니다.
- 답변을 고를 때마다 DB에 저장합니다.
- 4개 축으로 독서 성향을 계산합니다.
  - 지식 중심 ↔ 이야기 중심
  - 동양 배경 ↔ 서양 배경
  - 인기작 ↔ 새로운 발견
  - 가볍게 ↔ 깊이 있게
- 추천 결과 3권에 서로 다른 역할을 붙입니다.
  - 지금 바로 읽기
  - 한 단계 확장
  - 뜻밖의 발견
- 결과를 공개 코드로 다시 조회할 수 있습니다.
- 추천 피드백을 DB에 저장할 수 있습니다.

### 책 데이터

- 로컬 테스트를 위한 개발 도서 10권과 특성 37개가 준비되어 있습니다.
- Open Library에서 최대 500권을 수집할 수 있습니다.
- Open Library 500권을 MVP 추천 후보로 공개하는 명령이 있습니다.
- 공개된 책만 추천 후보가 되도록 상태를 관리합니다.

500권을 빠르게 추천 후보로 만들 때는 최소 특성 `G_NOVEL`, `VIS_TEXT`를 사용합니다. 이것은 “기본 후보가 될 수 있다”는 뜻이지, 모든 책의 분위기·난이도·세부 장르를 정확히 알아냈다는 뜻은 아닙니다.

### 팀 개발 환경

- Docker로 PostgreSQL을 한 번에 실행할 수 있습니다.
- migration, 특성, 개발 도서가 자동으로 준비됩니다.
- API와 화면을 각자 컴퓨터에서 실행해 볼 수 있습니다.
- MCP 도구로 외부 서지 후보를 검색할 수 있습니다.

자세한 실행 방법은 [팀 로컬 DB 연결·테스트 매뉴얼](team-local-db.md)에 있습니다.

## 6. AI는 어떤 일을 하나요?

AI는 Google Gemini API를 선택적으로 사용합니다.

1. DB와 추천 로직이 먼저 후보 책을 고릅니다.
2. Gemini는 책 제목과 일치한 특성만 받아 추천 이유 한 문장을 만듭니다.
3. `GEMINI_API_KEY`가 없거나 AI 호출에 실패하면 템플릿 문장을 보여 줍니다.

그래서 Gemini 키가 없어도 추천 기능과 팀 테스트는 계속 작동합니다. Gemini는 **추천 결정자**가 아니라 **설명 작성 도우미**입니다.

## 7. 팀원이 직접 확인하는 방법

프로젝트 루트에서 실행합니다.

```bash
npm install
npm --prefix frontend install
cp .env.example .env
npm run db:dev:up
```

그 다음 터미널 두 개를 열어 실행합니다.

```bash
npm run api:dev
```

```bash
npm --prefix frontend run dev
```

DB까지 실제로 저장되는지 확인하는 가장 중요한 명령은 아래입니다.

```bash
RECOMMENDATION_API_URL=http://localhost:3001 npm run demo:check
```

이 검사는 질문 12개 답변, 성향 계산, 추천 3권, 결과 재조회, 피드백 저장을 한 번에 확인합니다.

## 8. 아직 더 해야 할 일

프로토타입은 작동하지만, 학교나 실제 서비스에 사용하기 전에는 아래 작업이 더 필요합니다.

| 다음 과제 | 이유 |
| --- | --- |
| 500권의 소개, ISBN, 출판사, 페이지 수 보강 | 책 카드와 추천 근거를 더 믿을 수 있게 만들기 위해 |
| 세부 특성 검수 | 모든 책에 기본 특성만 붙이지 않고, 분위기·난이도·장르를 정확하게 분류하기 위해 |
| 사서·교사의 검토 | 학생에게 적절한 책인지 확인하기 위해 |
| Gemini 결과 점검 | 추천 이유에 사실과 다른 내용이 없는지 확인하기 위해 |
| 모바일 화면 검사 | 휴대전화에서도 글자와 버튼이 잘 보이는지 확인하기 위해 |
| 개인정보 정책 설계 | 실제 사용자 계정과 장기 기록을 다룰 때 안전하게 운영하기 위해 |

## 9. 꼭 기억할 점

- 로컬 DB 주소는 개발용입니다. 공용 DB 비밀번호나 API 키를 문서·채팅·Git에 올리면 안 됩니다.
- 외부에서 가져온 책 정보는 바로 사실이라고 믿지 않고 검수해야 합니다.
- 추천은 도움을 주는 도구이며, 학생의 취향이나 능력을 단정하는 평가 도구가 아닙니다.
- 테스트가 통과했다는 것은 기능이 작동한다는 뜻입니다. 책 데이터의 품질과 교육적 적절성은 별도로 계속 검토해야 합니다.
