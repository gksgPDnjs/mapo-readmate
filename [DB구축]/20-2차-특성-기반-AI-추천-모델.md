# 2차 특성 기반 AI 추천 모델

## 입력과 저장

`book_feature_v1.csv`의 `attribute_id`를 `catalog.feature_definitions.code`로 그대로 저장한다. 책별 특성은 `catalog.work_feature_values`에 기록하며, `review_status = 'approved'`인 값만 추천에 사용한다.

2차 설문 `deep-feature-v1`은 장르, 주제, 분위기, 문체, 결말, 시각 형식, 기대 효용, 회피 요소를 묻는다. 선택 결과는 `recommendation.profile_feature_preferences`에 저장한다.

| 응답 | 저장 값 | 추천 처리 |
| --- | --- | --- |
| 선호 | `preference = 'prefer'` | 일치 특성 수만큼 가점 |
| 회피 | `preference = 'avoid'` | 해당 특성 책을 후보에서 제외 |
| 미선택 | 저장하지 않음 | 점수·필터에 사용하지 않음 |

1차의 목적·배경·대중성·난이도 점수는 프로필 스냅샷의 연속형 축으로 보존한다. 2차 특성은 축을 덮어쓰지 않고, 추천 후보 필터와 순위 근거로만 사용한다.

## 추천 API

`POST /api/recommendations/preview`는 `preferredFeatureCodes`, `avoidedFeatureCodes`, `limit`을 받는다. 서버는 다음 순서로만 처리한다.

1. 공개된 작품·판본과 검수된 특성값만 DB에서 조회한다.
2. 회피 특성이 있는 후보를 제외한다.
3. 선호 특성 일치 개수로 순위화한다.
4. 상위 후보와 검증된 특성 코드만 Gemini에 전달해 한 문장 추천 설명을 만든다.
5. Gemini 응답 실패·미설정 시 검증 특성 기반 템플릿 설명을 사용한다.

AI는 책 후보를 새로 만들거나, 수상·판매량·줄거리 같은 DB에 없는 사실을 추가할 수 없다. 추천 실행을 영구 저장하는 API에서는 `recommendation_runs`, `recommendation_items`, `explanation_factors`, `explanation_renderings`에 입력 버전과 근거를 함께 기록한다.

## 키와 보안

- `GOOGLE_BOOKS_API_KEY`는 도서 메타데이터 수집용이며 Gemini 호출에 사용할 수 없다.
- `GEMINI_API_KEY`는 추천 설명 생성에만 사용하며 브라우저와 DB에 저장하지 않는다.
- 모든 키는 서버의 `.env` 또는 배포 secret store에서만 읽고, `VITE_` 접두사와 API 응답·로그에 넣지 않는다.
- 외부 API 원문은 `provenance.source_records`에 저장하되, 인증키는 적재 전에 제거한다.
