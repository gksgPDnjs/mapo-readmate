# DB·화면·AI 추천 연동 점검

## 점검 범위

- 2차 질문 DB 응답 → 화면 옵션 → 특성 코드 배열 변환
- 사용자 특성 코드 → DB 공개·검수 도서 조회 → 화면 도서 카드 표시
- DB 기반 후보 → AI/템플릿 추천 이유 생성
- 카탈로그 출처·특성·도서 현황을 확인하는 운영자 테스트 화면

## 통과 항목

| 항목 | 확인 방법 | 결과 |
|---|---|---|
| DB 연결 | `GET /health` | 통과: `status=ok`, `database=connected` 확인 |
| 2차 질문 로딩 | `GET /api/deep-questions` | 통과: 8개 문항과 옵션 반환 확인 |
| 사용자 입력 데이터화 | `DeepQuizScreen`이 선택 옵션을 `preferredFeatureCodes`·`avoidedFeatureCodes`로 변환 | 통과 |
| 추천 후보 선택 | 공개된 작품·판본과 승인된 특성만 사용 | 통과 |
| 추천 화면 표시 | 제목·저자·소개·일치 특성·점수가 있는 DB 응답 | 통과 |
| 추천 중복 제거 | 작품 ID 기준으로 판본 중복 제거 | 통과 |
| 입력 투명성 | 지원되지 않는 특성 코드를 `ignored*FeatureCodes`로 반환 | 통과 |
| 운영자 진단 | `#test`에서 카탈로그·출처·문항·추천 결과를 표시 | 통과 |
| 500권 후보 적재 | Open Library 원본 레코드 500건, 작품·판본 각 510건 확인 | 통과 |

## 미통과·보류 항목

| 항목 | 상태 | 이유 | 다음 조치 |
|---|---|---|---|
| 회피 조건의 의미 있는 필터링 | 미통과 | `AVOID_DARK`, `AVOID_HARD`, `AVOID_CRUEL`, `AVOID_LONG`에 대응하는 검수된 도서 특성값이 충분하지 않다. 현재 API는 근거 없는 제외를 하지 않고 `ignoredAvoidedFeatureCodes`에 표시한다. | 실제 수집·검수 단계에서 내용 경고, 난이도, 분량, 정서 특성을 정의하고 도서별 승인 값을 적재한다. |
| Gemini 설명 생성 | 보류 | `GEMINI_API_KEY`가 없는 환경에서는 안전한 템플릿 설명을 사용한다. 외부 모델 호출 품질은 검증하지 않았다. | 키가 설정된 스테이징 환경에서 환각·길이·한국어 품질 테스트를 추가한다. |
| 국립중앙도서관·정보나루 실제 적재 | 보류 | API 키 없이 실서비스 수집을 실행하지 않았다. Open Library 후보 500권은 적재됐지만, 추천용으로 검수된 도서는 개발 시드 10권이다. | 각 키를 설정하고 수집 실행 후 원본 레코드·ISBN·검수 상태를 점검한다. |
| 커버·외부 소개 노출 | 보류 | 자산 이용 권리 검토 전에는 표지 및 제공 문구를 화면에 노출하지 않는다. | `provenance.asset_rights`의 승인 기록이 있는 자산만 노출한다. |

## 실행 방법

API를 재시작한 뒤 다음을 실행한다.

```bash
npm run api:start
npm run recommendations:check
npm run catalog:check:500
```

브라우저에서는 `http://localhost:5174/#test`를 열어 DB 연결과 추천 결과를 확인한다.

## 추천·AI 경계

도서 후보와 순위는 DB의 공개 상태, 검수 상태, 특성 강도를 사용해 결정한다. AI는 후보를 새로 만들거나 순위를 바꾸지 않고, DB가 반환한 제목과 일치 특성만으로 추천 이유를 작성한다. 외부 AI 호출에 실패하면 템플릿 설명으로 대체한다.
