# 무료·유료 플랜, 권한 및 결제 모델

## 제품 계약

| 등급 | 로그인 | 취향 축 | 추천 | 목적 |
| --- | --- | --- | --- | --- |
| `free` | 불필요 | 핵심 4축 | 3권 | 빠른 결과와 기본 추천 |
| `premium` | 필요 | 핵심 4축 + 정교화 5축 = 9축 | 5권 | 더 세밀한 후보 선정과 근거 |

`quick` 4축·3권이 무료의 기본 결과다. `deep`은 유효한 `premium` 권한에서만 9축·5권으로 실행한다. 콘텐츠 경계, 청소년 안전 필터, 도서 기본 메타데이터와 추천 근거는 어떤 등급에서도 제한하지 않는다.

## 축 집합

| 집합 | `access_tier` | 축 |
| --- | --- | --- |
| `core_4` | `free` | `story_knowledge`, `reality_imagination`, `emotion_insight`, `light_deep` |
| `refined_9` | `premium` | `core_4` + `familiar_novel`, `rapid_contemplative`, `character_idea`, `personal_social`, `comfort_challenge` |

목적, 관심 주제, 가용 시간, 분량, 콘텐츠 경계는 등급과 무관한 컨텍스트다. 이들은 성격·학업 능력·민감 정체성을 뜻하는 축으로 사용하지 않는다.

## 테이블

| 테이블 | 핵심 열 | 제약 |
| --- | --- | --- |
| `identity.app_users` | `id`, `auth_user_id`, `created_at`, `deleted_at` | `auth_user_id` 유니크, Supabase `auth.users` FK |
| `billing.plans` | `id`, `code`, `version`, `access_tier`, `dimension_set_code`, `recommendation_count`, `billing_interval`, `status`, `feature_policy` | `(code, version)` 유니크 |
| `billing.entitlements` | `id`, `app_user_id`, `plan_id`, `capability_code`, `status`, `starts_at`, `ends_at`, `source_type`, `source_reference` | 유효 기간 중 같은 기능의 중복 활성 권한 금지 |
| `billing.subscriptions` | `id`, `app_user_id`, `plan_id`, `provider_code`, `provider_customer_ref`, `provider_subscription_ref`, `status`, `current_period_ends_at`, `cancel_at_period_end` | `(provider_code, provider_subscription_ref)` 유니크 |
| `billing.webhook_events` | `id`, `provider_code`, `provider_event_ref`, `event_type`, `payload_sha256`, `received_at`, `verified_at`, `processed_at`, `processing_status` | `(provider_code, provider_event_ref)` 유니크 |
| `billing.entitlement_usage` | `id`, `entitlement_id`, `quiz_attempt_id`, `recommendation_run_id`, `capability_code`, `consumed_at` | 실행별 사용 기록 |

## 권한 확인 규칙

1. Route Handler는 `quiz_attempt` 생성 전에 서버 측에서 권한을 해석한다. 클라이언트가 보낸 등급은 신뢰하지 않는다.
2. `deep` 시도는 인증된 `app_user`와 실행 시점에 유효한 `premium_recommendation` 권한이 모두 있어야 한다.
3. 해석한 `access_tier`, `dimension_set`, `plan version`, `entitlement_id`는 시도·프로필·추천 실행에 스냅샷으로 저장한다.
4. 구독 해지나 만료는 새 `deep` 실행만 막는다. 이미 생성된 추천과 과거 결제 근거는 수정하지 않는다.
5. 결제 웹훅은 서명 검증과 공급자 이벤트 ID의 멱등성 검사를 통과한 후에만 구독·권한을 갱신한다.

## 결제·개인정보 경계

- 카드 번호, CVC, 계좌번호는 저장하지 않는다. 결제 공급자의 불투명 참조값만 보관한다.
- 무료 익명 세션은 결제 테이블에 행을 만들지 않는다. 결제 또는 결과 저장을 선택할 때만 Supabase Auth 계정에 연결한다.
- 익명 세션 연결은 명시 동의 후에만 수행하며, 연결 전 세션 데이터의 보존 기간은 기존 정책을 유지한다.
- 청소년 결제와 연령 확인은 서비스 정책·결제 공급자·법률 검토 후 별도 사용자 흐름으로 처리한다. 생년월일을 추천 프로필에 넣지 않는다.

## 운영 규칙

- 가격과 기능은 `billing.plans.version`으로 변경 이력을 남긴다. 기존 구독자가 어떤 조건으로 구매했는지 덮어쓰지 않는다.
- 운영자가 수동으로 권한을 부여하거나 철회하면 감사 로그를 남기고 `source_type = 'admin_grant'`로 기록한다.
- 유료·무료 품질 평가는 서로 분리해 측정한다. 유료화가 안전성, 중복 방지, 데이터 출처 검증을 약화시키면 안 된다.
